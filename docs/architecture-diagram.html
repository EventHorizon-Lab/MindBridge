MindBridge — Agentic Native Embodied Memory System

Memory-as-a-Service，端云分离 · 证据优先 · 冻结模型 · 单库收敛
Model is frozen, Memory is alive; evidence is durable, representations are rebuildable.

写入路径 · 异步且幂等

  • • observe 只做三件事：查幂等键、落 observation + media 行、投递任务，然后 202 + job_id 返回
  • • Worker 抢占任务时带 attempt 计数，重复投递返回已有终态；jobs 表是唯一的真相
  • • 感知输出必须落到 EvidenceSpan 才收，否则整个 attempt 拒收
  • • 切片与图向量 asyncio.gather 并发，最后一次事务提交全部 8 类产物
  • • 切片按落地后的事件跨度切，不切整文件——向量的精度不会超过切它的那段

召回路径 · 混合且可追证

  • • 三路 ANN 按 object_type 分开：EvidenceSpan / MemoryRecord / (Event·Claim·Entity)
  • • 第三路是图入口——具名实体可以直接命中并展开邻居，不再依赖 2-hop peer join
  • • 有文本查询时并发跑词法检索（mindbridge_text tsvector，保留 <voice_0> 这类标记）
  • • 四路候选用 RRF（k=60） 融合，不比较异构原始分
  • • 回答走多轮反思波次；无证据支撑就弃权，返回结果永远带 evidence_ids

不可变的架构约束

  • • 证据优先：只有 MediaObject / Observation / EvidenceSpan 是终局证据，其余都可重建
  • • 冻结模型：不做任何权重微调；系统靠记忆状态、索引、原型和生命周期策略自学习
  • • 两个插口：模型层只有 Generator 和 Embedder，任务语义不外包给供应商
  • • 一套主库：向量 / 全文 / 关系 / 时间同库同事务，没有独立向量库或图库
  • • 三种可信度：verified（传感器证据）· attested（调用者陈述）· unverified

边界与分层纪律

  • • 依赖方向单向：core ← application ← infrastructure / models / api / edge
  • • Kernel 只认 ports.py 的 Protocol，PostgreSQL 与 S3 都能整体替换
  • • benchmarks/ 是叶子：只能调公开 SDK 和 contracts，任何产品模块都不许 import 它——所以它有自己的二进制 mindbridge-bench
  • • 身份模板 AES-GCM 加密留在端上；删除沿 /v1/deletions 回放到设备，是真删对象不是打标记
  • • 媒体 URI 必须是 s3://<配置 bucket>/tenants/<tenant>/…，带 query / fragment 或越出前缀一律拒签
  • • 凭据只从环境读，进程列表、录制的命令和 systemd unit 里都不会带
