# 第三轮：按义务搜索证明 DAG

## 结论与机制

本轮实现了三个研究版本，并用对抗反例否定前两版的资源处理。最终研究版本 v3
在已知容量矩阵中恢复了全部合法支持，也使预算内的完整证据交付成为可检验的对象。
这支持继续研究该机制，不构成自然场景泛化或生产可用性的证明。

新机制针对 MindBridge 的记忆语义：**为当前结论寻找两份完整且独立的证明 DAG**。
它没有修改回答提示、形成提案、可见性阈值或检索排序。

对目标 q，一份证明 H 必须为每个衍生节点选择一个评估，并保留该评估全部 AND
来源；OR 评估允许回溯。每侧内部共享子证明，每个节点只选择一个 clause，加入新边
时检查成环。两份证明必须来自不同的顶层评估，其 capture 和中间节点除 q 外不相交。
每份证明分数是所有必要节点/评估置信度的最小值；两份独立证明使用现有的组合公式。

搜索把这些条件转成义务：展开时立即拒绝跨侧重叠、循环、缺失来源及超预算分支。
完成后返回包含节点与所选完整来源的证书。支持数与最高分仍分别求最大值，不能用
获得高分的单一证明冒充两份独立支持。

这是一项面向 MindBridge 证据契约的算法组合与实现创新，不声称回溯、DAG 或约束
搜索本身是新发明。它也尚未解决真实 capture 同源识别、跨时身份形成或模型输出错误。

## 对照和消融

所有主要数字使用 v3；[协议](2026-09-13-witness-search-protocol.md)记录了版本修订。

| 对照 | 算法 | 资源 |
| --- | --- | --- |
| A | 现有逐节点缓存并传播证明 | 64 条缓存证明，4,096 步 |
| B | 按义务搜索证明 DAG | 4,096 个搜索状态/配对调度步骤 |
| C | B 去掉中途跨侧排斥，完成后才检查独立性 | 与 B 相同上限 |
| D | A 增加资源 | 1,024 条缓存证明，200,000 步，仅作诊断 |

A 与 B 的一步含义不同，因此相同数值上限不等于相同计算量。报告同时保留实测时间、
独立 tracemalloc 测量及截断状态。各策略执行顺序固定种子随机化，未隔离系统背景
负载；部分 SDK 执行与其他实验或测试重叠，不以它们声称生产延迟优势。

v3 的失败 clause 扫描、无环可达检查和输入排序没有逐项扣减状态预算，取得下一状态
也可能先做这些工作。因此 4,096 不是 CPU 时间或全部基础操作的硬上限；生产采用前
仍需要完整计费或截止时间。这一剩余限制没有通过提高配额或隐去退化来处理。

## 公开 SDK 回放

v3 使用 81 个配对条件、162 个独立物理库：第一轮 13 个结构各走五种载体，再加
第二轮 8 个容量结构的两个变体。A/B 都使用现有 `independent-v1` 存储策略；B 只在
研究进程替换纯支持函数。输入提案、巩固调用数、输入记录/字符数和嵌入条目均一致。

| 指标 | A | B |
| --- | --- | --- |
| 正例长期判断可见 | 37/38 | 38/38 |
| 负例错误可见 | 0/43 | 0/43 |
| 删除后结果正确 | 10/10 | 10/10 |
| 原生 Context Compiler 交付正例 | 34/38 | 34/38 |

唯一变化是宽度 64 的独立支持案例、seed 7101：confidence 从 0.6 恢复为 0.84，
目标从隐藏变为可见。原生编译交付没有提高，这与尚未集成交付选择器一致。
配对写入耗时比的中位数为 0.997，仅作局部观测，不宣称整体加速。

五种载体使用固定提案、常量嵌入及合成媒体字节，没有实际感知模型；同一结构跨载体
不是独立的记忆能力证据。v1/v2 也各完成相同的 162 库回放，三版共 486 次，不能
把重复试验合并成更大的独立样本量。

## 预算内交付完整证明

离线交付实验固定每个记录 100 字符、总字符预算 6,400，并比较不同 item 预算。
目标已知且证据图完整可得；不包含检索、格式化开销和真实模型输出。

| Item 上限，每组 168 正例 | 全部引证并集可交付 | 完整证明选择可交付 |
| --- | --- | --- |
| 4 | 0 | 28 |
| 16 | 4 | 56 |
| 64 | 40 | 112 |

两种策略需要相同的两份独立支持及至少 0.84 的分数。提升来自只交付满足义务的完整
替代证明，而没有删除必要 AND 来源。深度超过预算的证明仍然拒绝。这里是已知图上
的离线证书选择，不是已经集成的 SDK Context Compiler 功能；真实序列化后的总预算
仍需另行验证。

对抗审查还指出：count 证书和最高 confidence 证书可能不同，各自符合预算的两组
证书合并后可能超限。离线交付选择器在实际交付并集上重新核算两项义务和成本，
不满足就拒绝。它仅比较搜索保留的证书，可能漏掉未保留但可行的其他组合。

## 对抗审查推动的三次迭代

1. v1 没有发现证明正确性错误，但在预算之外物化所有顶层证明对，且共享 DAG
   展开成树后触发递归溢出。初版被否定，源码和结果保留。
2. v2 改用惰性配对、显式栈和共享证书前缀，修复崩溃；但 24 节点的共享 AND 图
   仍耗尽 4,096 步、返回零支持，A 却能得到一份支持。第二版仍不接受。
3. v3 改用每侧共享的证明 DAG，从机制上消除同侧重复展开；同时保持跨侧独立性
   检查和逐边无环验证。资源修复没有改变评分规则。

从有限证明树到 DAG 的等价性理由是：对每个重复节点，选择原完整证明中最小高度
的出现子树。沿所选边，最小可用高度严格下降，因此不会成环；所需节点是原证明的
子集，瓶颈分数不会下降。两侧分别这样压缩，不会新引入跨侧重叠。这个论证支持
表示方式的选择，具体实现仍由独立 oracle 和证书核验检查。

v3 在原有 24 个固定反例和 2,000 个随机图上完成 24,960 次预算/命名测试；另有
36,432 次 item/字符预算测试，以及新增 6,050 个小循环/出口图的 18,150 次检查。
这些调用未发现超出独立 oracle 的支持/分数、无效 DAG 证书或未截断却不精确的结果。
有限预算下仍有低于 oracle 的结果，截断不是获得完整结论的证明。

随机 2,000 图中只有 38 个两份支持正例，不能把调用数视为正例覆盖数。审查另外验证
了联合交付义务的六个阈值案例：需要 count=2、confidence=0.99 的证书并集有 5 个
记录，即使两组最优证书各只有 3 个，预算为 3 或 4 时也拒绝，预算为 5 时才接受。

v2 失败的 24/26/28 节点共享 AND 图，在 v3 中分别使用 25/27/29 步得到完整的一份
支持；扩展到 202 节点时使用 203 步。这里修复的是同侧重复展开，不能外推为所有
AND/OR 搜索都具有线性复杂度。

## 复现边界

本轮无外部模型调用。所有研究代码、manifest、逐行数据及各版失败保留在
`autoresearch/corroboration-witness-260913/`，该目录按仓库规则忽略。

- `witness_v1.py`、`witness_v2.py`、`witness_v3.py`：各版冻结原型。
- `run_v*.py`、`results-v*/`：相同容量、公开 SDK、交付和内存测量。
- `delivery.py`、`delivery_v3.py`：按实际证书并集核算交付义务。
- `adversary/`：独立 oracle、固定与随机输入、证书验证、资源反例和审查结果。

预算审查元数据最初仅记录共用执行器哈希，缺少 v3 入口与 DAG 验证器；原 JSON
保留，补充信息另记于 `adversary/provenance-amendment.json`。三版原型哈希均与各自
调用前 manifest 一致。

产品代码与默认策略未改变。源码集合 SHA256 仍为
`264e179819e09ecd43c701355bd193335bb8aaa5df98153783972b7e052793f7`。
v3 尚不支持产品推广结论；下一阶段必须验证真实形成输入、SQLite 图读取截断、
实际 ContextBundle 序列化以及更复杂的 OR 组合压力，不能仅重复这套已知回归集。
后续实际验证见[第四轮结果](2026-09-13-live-context-results.md)：本批真实形成和有效
Context 交付没有收益，直接缩减闭包的额外交付未通过现有公开引证契约。

本轮 Python 3.14.2 下全部 2,251 项测试通过（399.20 秒）；lockfile、Ruff 格式与
检查、mypy 均通过。研究原型的正确性另由上述独立实验核验，产品测试通过不替代
研究机制的有效性证据。固定版本 Markdown 检查通过；链接检查覆盖 599 个链接，
零错误，包含 8 个重定向。
