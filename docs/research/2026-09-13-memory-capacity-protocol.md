# 第二轮：记忆容量、来源依赖与形成连续性

## 冻结问题与边界

承接第一轮，不改变回答提示、拒绝规则或形成模型提示。当前实验机制为
`independent-v1`，仍默认关闭。先前的小图正确率不能说明长历史上的能力。

本轮有两项已发现的开发反例：64 条同一顶层评估的替代证明可能挤掉另一份独立
评估；按评估多样性驱逐弱证明又可能删除唯一不重叠见证。它们属于开发发现，不能
在报告中冒充从未见过的保留集。

本轮环境为 Linux、Python 3.14.2；此前 Python 3.13 解释器已不可用，使用同一
`uv.lock` 恢复全部依赖。不跨两轮比较绝对耗时。新结果单独保存，原始失败不覆盖。

## 三组实验

1. **容量曲线。** 固定宽度 8、16、32、48、63、64、96，串联深度 0、8、32、60、64、96。
   对比原始节点名和固定 seed 生成的重命名。正例存在独立原始见证；负例共享来源或
   中间摘要。纯算法使用默认 64 条证明、4,096 步；充足预算对照用于诊断，不作为可
   部署候选。实际 SDK 的 SQLite 读取上限保持不变，单独检查选定代表图。
2. **来源申报。** 相同物理事件的复制件分别带正确 capture group、缺失标记和不同
   错误标记；另有真实独立事件对照。通过公开 Memory SDK 比较 legacy 与候选的可见性，
   区分声明证据图上的计算正确与物理事件上的错误佐证。不给模型评分标签。
3. **真实形成。** 使用已有配置中的 qwen3.8-27b，固定 temperature=0、seed、输出上限，
   不改提示。四类两条观察：明确人名、单一人物后的代词、明确的另一个人、两个人物
   后的歧义代词。比较批量/逐条写入、legacy/候选、两次重复；共 32 个独立物理库，
   最多 48 次形成调用。相同日程内比较证据策略；批量与逐条请求次数不同，不称为
   同计算预算的算法优劣比较。常量嵌入排除检索因素，不调用 answerer 或 LLM judge。

真实形成在调用前保存用例、预期人物及必要来源索引。记录全部衍生文本、声明引证、
错误和耗时。明确人名必须形成对应人物事实；跨观察代词解析必须同时引用两条观察；
歧义代词不应绑定到任一具体人物。字面自动评分只作为辅助，逐例人工式代码审阅结果。
首个连通性 probe 已成功，不计入正式样本。

运行中预算口径修正：48 指 formation 调用次数；产品适配器在 JSON 验证失败时会再
请求一次，这与 HTTP 客户端 `max_retries=0` 不同。执行脚本最初误将 HTTP 总次数也
封顶为 48。修正指令实际到达时首次运行已经结束，最后 5 个逻辑单元的 7 次 formation
被执行器阻断。原 32 条记录完整保留，只补跑全部这 5 个受限单元，禁止重试真正的
模型/格式失败；无论补跑成功与否都采用补跑结果，不择优。因临时库已关闭，补跑需
新开 5 个物理库并重放完整输入，形成 32 个逻辑单元、37 次物理尝试。追加预算最多
10 次 formation、20 次 HTTP，累计 HTTP 防失控上限为 96。该修正属于执行基础设施
修复，已偏离最初的调用总数，报告必须同时展示原始与补跑记录及其时序限制。
初始自动评分要求 typed subject 包含名字，但 EVENT 的 subject 合法地可为空；保留
原评分，另做明确标注的内容语义与引证审阅，不将合法表示差异直接判成记忆失败。

## 候选与接受条件

评估多样性保留是独立研究候选，已出现弱而独立见证丢失的反例，禁止仅凭修复 64 条
替代路径案例就提升产品。另一候选只跳过同顶层评估内部不可能佐证的比较；必须对照
完整证明 oracle，且不能通过提高步数或证明上限取得收益。

保持原始 capture 和中间推导的完整性是硬条件。任何候选若在固定负例上增加错误
佐证，或在已声明的正例上新增漏学，则本轮不推广到产品。扩大上限只能作为资源
消融，不能包装成算法改进。真实形成实验允许结论为无收益或暴露其他瓶颈。

报告必须分别列出开发反例、固定容量矩阵、SDK 生命周期和真实模型结果，保留
未解决的来源声明依赖、截断、模型失败与评分不确定性。本轮无需发布或修改默认策略。
