# 第五轮协议：历史身份恢复与显式证明交付

## 两项独立假设

身份恢复：在形成当前观察之前，从真实历史身份产物回溯原始见证，与同预算的最新
时间窗口、词项检索比较，是否提高具名且完整引证的记忆形成，同时不增加错误归人。

证明交付：采用明确的新研究格式，保留权威记录及完整来源列表，同时携带本次选定
的完整证明，是否在相同序列化字节预算内提高有效交付。它不称为现有 ContextBundle，
也不通过改写 MemoryContext 来伪装兼容性。

## 身份恢复对照

六套历史，各包含四条普通文本，经公共 SDK 的真实形成模型建立身份候选。每套两个
当前事实，比较 H0 无历史、W 最新窗口、S 通用词项检索、I 身份见证恢复，共 48 次
目标 FORM；历史另有六次 FORM。正式总上限 60 FORM、180 HTTP，保留结构重试和失败。

模型沿用 qwen3.8-27b、原形成提示、temperature=0、固定 seed、1,500 输出 token，
25 秒请求超时、客户端零重试。W/S/I 历史预算均最多两条、640 字符，报告实际 token，
不声称输入 token 数完全一致。S 是词项检索，不能写成已验证的语义嵌入对照。

I 只使用真实形成的 ENTITY/身份 RELATION 及权威来源，不读取预期姓名、案例类别或
答案标签。覆盖唯一人物、竞争人物、人物切换、旧身份删除、更正和显式实名控制。
删除用公共 delete，不把软遗忘误当撤销。

当前形成 API 只允许批内来源。研究使用独立库的延迟/重放入口，将选中历史与当前
观察通过公共 add_many 共同形成；只计当前观察的产物，历史重新形成不算收益。
它尚不等于已完成历史可以直接注入产品 Formation 的新能力。

评分同时检查姓名/事实、当前与必要历史引证、歧义保留、错误归人、空输出与异常。
所有选择轨迹、原始请求/提案、实际传入源 ID 和最终 SDK 记录均保留。

## 证明交付研究契约

Envelope 使用独立版本号，包含 goal、scope、可信 snapshot 标识、budget、status、
权威 records、claims、proofs、evidence_roles 和 refusals。proofs 明确列出每份证明
选中的完整 AND edges 与原始 roots；不同证明表达 OR 替代。capture 与中间节点的
独立性由接收端从证明重建，不能信任发送端自报。

每个交付的衍生记录都必须证明其权威 confidence/count，包括作为中间支持的记录。
evidence_roles 区分实际选定的直接来源与仅属权威来源并集的备用引用。备用引用不
声称已交付，但也不能指向接收端不允许访问的 ID。已知冲突从可信 snapshot 计算，
不得由发送包自身决定是否存在。

接收端独立接收 expected goal、scope、budget、requested IDs 及最新可信 snapshot；
不能让包自己选择旧状态或提高预算。验证实际 canonical JSON UTF-8 bytes 的总长度，
包括正文、证明、头、备用来源与拒绝。拒绝重复 key、NaN、错误数字类型和非规范编码。
如果连最小拒绝包也放不进预算，传输层硬失败，不发送超预算“拒绝”。

Full 与 Selected 使用相同研究格式、记录、证明规则和接收端。Full 物化完整权威
祖先闭包；Selected 只物化证据义务所需记录。两者都必须满足原请求及所有衍生记录的
证明要求，不通过降低所需支持或隐去竞争值获得收益。

本轮先限定纯文本记录；非空 assets 被拒绝，不把媒体引用当作原媒体已交付。可信
snapshot 在静止的研究库上通过 SDK 记录与权威 SQLite clause loader 建立，生产环境
中的一致读快照、权限获取和跨进程发布尚不在本轮实现范围内。

## 独立证伪与复现

独立接收端不导入发送端 solver/验证逻辑。攻击包括删除 AND 来源、替换 clause、
伪造分数、重复 capture、共享中间节点、旧 snapshot、漏掉竞争断言、中间高分偷渡、
越界引用和真实字节超限。传输有效、拒绝有效和目标成功交付分别统计。

所有输入、脚本和预算在正式调用前固定哈希，失败与修订不覆盖。两项实验分别位于
忽略目录 `autoresearch/identity-witness-260913/` 与 `autoresearch/proof-envelope-260913/`。
结果只能支持对应机制的有限结论，不能由合成文本/图外推机器人多模态实地效果。
