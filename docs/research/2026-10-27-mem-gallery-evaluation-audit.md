## 第一性原理：分数不能直接充当组件归因

最终分数是输入保真、记忆表示、候选检索、证据筛选、实际媒体交付、答案生成、协议序列化及评分
共同作用的结果。要把损失归给某个组件，需要固定其他条件并进行干预。来源 ID 出现，只说明
该来源可追踪；不证明关键句未被截断、正确像素被看见、实体绑定正确或模型理解了证据。

诊断结构本身把 `fact_span_coverage`、`perception_quality`、`causal_attribution` 留为 null。
不能把这些未知量解释成已经通过。也不能把语义 judge 判满分解释成事实正确，尤其当其输出解析
会离散化评分时。本次依照请求，不比较 judge 模型。

## 截图各项解释的归属

| 现象 | 已确认的原因或约束 | 应归属哪里 |
| --- | --- | --- |
| 85 道 AR 返回内部拒答标记，58 道返回标准拒答 | 官方要求条件式 `Not mentioned.`；产品 system 要求另一标记，strict 流式结果保留该标记 | 适配器与产品回答协议不匹配；不证明检索失败 |
| 正确答案夹带日期、人物和解释 | 适配器已有官方“简洁但完整”要求；实际 reader 仍生成长答案 | 回答遵循与序列化问题；对纯记忆后端的能力归因不足 |
| `Yes—Leo ...` 对 `Yes.` 得零 | 官方只替换 ASCII 标点；Unicode 长破折号保留，`yes—leo` 是整个 token | 官方词面指标的局限；不是本地评分器 bug |
| `Dog` 对 `Toy terrier`、服装缺少具体类别、综合题缺少要点 | 简化措辞无法补回缺失信息 | 真实端到端能力不足；感知、绑定、交付或 reader 谁负责仍需干预 |
| 标注来源齐全时 F1 仍低 | 来源级覆盖不等于充分、正确、无干扰的证据 | 支持进一步诊断 reader 与交付，不能直接排除检索或表示问题 |
| 五个执行错误 | 空预测计零；全部改成满分的数学上界为 0.2922 个百分点 | 真实可靠性问题，但无法解释主要分差 |

AR 官方提示带条件，官方 runner 也按 AR/CD/VS 类型选择格式约束。因此，复现这些条件式提示
本身不是标签泄漏。把 AR 标签直接当成“这题答案必定未知”再硬编码输出，则绕过了证据判断。

85 个标记直接替换成标准拒答，历史 F1 的反事实增量为 `85/1711`，即 **4.9679 个百分点**。
这只是协议损失的离线诊断，不是修复后的实测成绩，也不能写回原始 run。
非 AR 还有 64 个含标记的回答，说明“所有内部拒答都给分”会掩盖其他题型中的真实失败。

截图所举 `matplotlib` 的长答案确实只有 0.105263 F1，`Yes—Leo ...` 确实为零。
按问题要求直接回答 `matplotlib` 或 `Yes.` 是合法的任务遵循；修改分词器让长答案自动得分，
或利用参考答案裁剪预测，则改变了评价对象。

## 召回证据说明了什么

在有 clue 的 1,527 题中，输入来源齐全 1,527 题，100 个候选中的来源齐全 1,504 题，
最终请求中的来源齐全 1,419 题；平均来源 recall 为 **96.8709%**。
排除五个执行错误后，1,414 道来源齐全题的 F1 为 **75.4952%**。
候选齐全但最终请求不齐全有 85 题；另有 23 题在候选阶段就未集齐来源。
这些集合是观察性切片，不是可相加的因果损失分解。

对照 1,711 个逐题记录，可复现 352 个“judge 满分但 F1 小于 0.5”。这一计数包含格式差异、
答案多写、同义表达以及可能的 judge 假阳性，不能全部改称“冤枉分”。
输入 3,962 条记忆无入库失败；487 个带查询图片的问题可以在准备的请求中找到对应图片。
这排除了这条查询图链路的系统性漏传，不证明图片已被远端成功理解，也不证明全部历史媒体完整。

更有辨别力的后续实验应使用独立开发集：固定同一批 reader 请求，分别提供完整原始 clue 图文、
已验证的事实文本、原有证据与干扰证据，比较原始答案的完整性和正确率。
产品和多个基线还应使用同一 reader、预算和回答协议。此次没有运行这些质量干预实验。

## 与官方实现的逐项比较

依据固定版本的
[官方 runner](https://github.com/YuanchenBei/Mem-Gallery/blob/a93959e1e978a6a7d77798ae92c2ffe41c538c62/benchmark/run/run_bench.py)、
[评价脚本](https://github.com/YuanchenBei/Mem-Gallery/blob/a93959e1e978a6a7d77798ae92c2ffe41c538c62/benchmark/memengine/evaluate/evaluation.py)及
[system prompt](https://github.com/YuanchenBei/Mem-Gallery/blob/a93959e1e978a6a7d77798ae92c2ffe41c538c62/benchmark/prompt/sys_prompt.txt)。
原论文也明确列出 F1、BLEU-1、EM 及检索 precision/recall/hit，见
[Mem-Gallery](https://www.alphaxiv.org/pdf/2601.03515)。

| 边界 | 核验结果 |
| --- | --- |
| 数据、题量、类型、参考答案、clue | 固定数据摘要一致；20 topic、1,711 QA、九类能力 |
| 多模态输入 | 每轮用户与 assistant、日期、Image ID 和原图进入适配器；查询原图保留；未注入参考答案或 clue |
| 主评分与聚合 | 原始回答的五项词面指标逐题一致；总体按问题加权，而非九类平均或 topic 平均 |
| 空 clue 检索评分 | 原实现省略 184 个 AR；官方保留并计零，造成检索均值分母不一致，已修复 |
| 排名重复来源 | 纯评分 helper 原来先去重再截断；官方 evaluator 先截断再去重，已修复；本次真实排名不受影响 |
| Unicode 边界 | 官方使用 `regex`，原实现用 `re`；组合重音字存在反例，已修复；本次回答无差异 |
| 指标身份 | 原来误把 EM 和三个检索指标归为非官方，已修复；generic source coverage 仍是不同的本地诊断 |
| 回答格式 | 简洁回答及 AR/CD/VS 的条件式约束与官方一致；产品 system 的拒答要求仍构成冲突 |
| 更新语义 | 官方 system 明确要求同一事件以最新信息为准；该规则没有被等价复现，产品约束也不能仅凭时间解决冲突 |
| 实验可比性 | MindBridge 自有 reader、证据预算和系统提示；评分一致不等于复现官方系统或模型受控比较 |

官方论文的 top-K 基线默认 K=10；本次的检索候选、字符预算与 `recall_limit` 描述了另一种
端到端系统。可以用相同官方评分器评价它，但不能把该分数解释成固定 reader 和预算后的记忆模块净贡献。
同理，“最新信息优先”是这个基准的任务假设，不适合无条件写入产品通用冲突解决规则。

旧的 R@10 是 1,527 道有 clue 题上的 **90.3748%**；官方脚本分母下为 **80.6560%**。
两者差异来自零 clue 行是否进入分母，不是记忆质量改变。官方 P@10 为 **20.8007%**，
Hit@10 为 **86.3238%**。截图 96.87% 是最终请求层的来源 recall，和 R@10 的阶段与 K 均不同。

## 修复、复算与防止 reward hacking

本次只修复确定性评分实现与指标标记，协议版本为 `mem_gallery_scorer_a93959e1e978_v2`。
把已有传递依赖 `regex` 显式声明在 benchmarks extra，不改变任何已锁定的包版本。
WorldMemArena 的旧归一化路径保持独立。回归用例涵盖空 clue、去重顺序、Unicode 重音、
长破折号、十进制、图像 ID、词干、重复词和空答案。

可用独立官方源码重新核验；脚本先核对完整源码哈希，仅执行五个纯评分函数。
`--official-evaluator` 指向上述固定提交的 `evaluation.py`，默认要求完整 1,711 题：

```bash
uv run --frozen python benchmarks/mem_gallery_parity.py \
  --samples /path/to/run/samples.jsonl \
  --official-evaluator /path/to/Mem-Gallery/benchmark/memengine/evaluate/evaluation.py \
  --output /tmp/mem-gallery-parity.json
```

需要保持的边界：不更改官方分词以适应本系统输出，不给所有拒答自动满分，不按题型硬编码答案，
不删除困难题、错误请求或拒答题，不将语义 judge 替代 F1，不将诊断重算当成新成绩。
简短且完整的回答、明确的拒答序列化、准确的来源媒体绑定都是正当改进，但须在新 run 中评价。
已查看的完整基准不能重新称作未暴露 holdout；后续质量提升需用独立测试集检验。
