# 选定证明交付：显式协议实验

本轮证明了一个有限结论：在已知证据图和明确请求的记录上，单独定义选定证明的
交付协议，可以减少物化的来源，并通过独立接收端验证。它尚未改善真实形成记录
的交付，也不是已接入产品的 ContextBundle 功能。

实验遵循[第五轮协议](2026-09-13-identity-proof-protocol.md)，与
[历史身份实验](2026-09-13-identity-witness-results.md)分别计分。

## 契约与公平对照

研究版本 `mindbridge-proof-envelope/0` 保留完整权威 MemoryRecord，包括原始
`context.evidence_ids`。额外的 `proofs` 明确列出选中的 AND edges 和 raw roots；
`evidence_roles` 区分本次选定来源与仅属于权威来源并集的备用引用。备用引用不
声称已经物化，也不允许指向接收端无权获得的 ID。

Full 和 Selected 使用同一格式、同一证明义务和同一独立接收器。Full 物化全部
权威祖先，Selected 物化足够的证明及其递归义务。每个交付的衍生记录都必须证明
其 confidence/count，包括中间节点；不能只证明目标而携带未经支持的高分中间记忆。

接收器的 expected goal、scope、budget、requested IDs 和最新 trusted snapshot
来自包外。它重建证明、capture 与中间节点重叠，计算实际支持，并检查完整 canonical
JSON UTF-8 字节数，包括头、记录、证明和拒绝。拒绝也超预算时不发送任何包。

本轮从静止的公共 SDK 实验库读取权威记录和 SQLite active clauses。修订版将有效期、
记录时间、退休、可见性和遗忘纳入资格判断，参考时刻固定为
`2026-09-14 05:14:02 UTC`。这不是支持任意历史时点的生产一致快照服务；权限列表也
只是实验信任输入，未实现新的用户权限系统。媒体 assets 非空时拒绝。

## A/B 结果

主实验共 186 个实际序列化包：五个结构图、26 个真实模型形成的既有记录，分别使用
`3 records / 8,000 bytes`、`6 / 16,000`、`24 / 64,000` 三档预算。每个条件配对
Full/Selected；结构图的不可见目标和已撤销目标仍留在分母，不以删除难例增加指标。

| 数据 | Full 有效交付 | Selected 有效交付 | 无效包 |
| --- | ---: | ---: | ---: |
| 五个结构图 × 三档预算 | 3/15 | 7/15 | 两组均 0 |
| 26 个真实形成记录 × 三档预算 | 66/78 | 66/78 | 两组均 0 |

这里的有效交付是明确请求的存储断言及其合法证明到达独立接收器，不包含检索排名、
下游回答质量或该断言在现实中的真实性。真实记录中的姓名/事实错误不会被协议修正。
这些记录来自上一轮真实模型调用，本轮交付矩阵没有新增模型调用。

在宽预算下，完整消息的空间变化如下。两组交付相同目标及其要求的支持。

| 图 | Full 记录 / bytes | Selected 记录 / bytes |
| --- | ---: | ---: |
| 八个 OR 来源 | 9 / 11,424 | 3 / 5,316 |
| 四组联合来源 | 9 / 11,692 | 5 / 7,620 |
| 多层 OR | 11 / 15,383 | 6 / 10,293 |

主结果观察后另行冻结了一项事后诊断：固定 64 个记录上限，只改变 8,000、11,000、
16,000 bytes，复用五个已知图。Full 为 3/15，Selected 为 8/15，30 个包全部有效。
它表明收益不仅来自记录数量上限，也涉及实际字节成本；它不是独立保留集或泛化证据。

## 对抗审查及保留的失败

独立审查没有导入发送端 solver。主矩阵的 186 个实际包全部重新读取验证；九个
snapshot 的全记录集合、内容、元数据、raw 首版置信度、capture group 和 active AND
clauses 与 SQLite 核对。衍生记录所需 count 另用独立穷举核对，避免生产者和验证者
共用同一搜索结果而相互确认。

审查暴露并修复了两个反例，原版本和失败产物均保留：

1. 初版 snapshot 只检查 visible/retired，导致真实 SDK 创建的已过期和未来观察被当作
   current 记录交付，字节正确的接收器也会接受错误的外部信任输入。修订了资格过滤，
   并保留初版 186 包与修订版矩阵；两版主矩阵数值相同不代表初版没有漏洞。
2. 初版独立接收器反复遍历共享 AND DAG。一个 38 记录、22,709 bytes 的控制在两秒
   内未完成；保存原版本后加入已完成节点分数缓存，约 0.004 秒完成。该单例用于
   证明验证器复杂度风险，不作为产品性能提升数据。

接收器另有 36 个手工控制，覆盖完整 AND、共享 capture/中间节点、分数伪造、旧
snapshot、中间高分偷渡、漏竞争断言、权限引用和线格式等边界。有效拒绝与目标成功
交付单独统计，不能靠“全部拒绝”获得交付收益。

实际包的 27 个变异/正向控制也全部符合预期，另有八个有效期、遗忘和可见性边界。
ASCII 包在 5,315 bytes 恰好交付，少一字节拒绝；Unicode 包为 7,358 bytes、5,958
字符，同样严格按 bytes 判定。1 byte 预算在传输层失败，不发送超预算拒绝。真实
SQLite 副本经公共 SDK 删除来源后，旧包因 snapshot 不匹配被拒绝。权限、capture
别名与竞争值控制修改的是外部可信实验状态，不代表已测试生产权限系统。

事后字节诊断的 30 个包及五份 snapshot 也通过独立重新读取验证。修订版主矩阵与
该诊断合计 216 个包；这些配对预算条件不应当作 216 个独立现实样本。

## 结论边界与复现

可以保留显式证明协议作为研究方向：它解决了上一轮“删掉备用来源后仍冒充完整
ContextBundle”的表达缺口。当前产品 API、存储格式和默认行为没有因本轮而改变。

尚不能据此宣布记忆能力泛化提升。真实形成轨道没有收益；输入是明确的目标 ID，
而不是自动检索目标；多模态原始资产、并发一致性、历史 clause 版本、生产权限获取
和下游 Agent 使用协议的能力都没有在本轮证明。证书选择也不是全局最优打包算法。

可复现实验位于忽略目录 `autoresearch/proof-envelope-260913/`：

- `producer.py`、`run.py`、`byte_trial.py`：发送端、主实验和事后字节诊断。
- `trial-v1/`、`trial-v2/`：版本化 manifest、snapshot、请求、原始 `.bin` 和统计。
- `byte-diagnostic/`：事后诊断的冻结说明、全部原始包与统计。
- `adversary/`：独立接收器、冻结旧版本、手工控制、复杂度反例和 SQLite 审计。

上述目录不属于产品发布包；正式代码不依赖研究 harness。
