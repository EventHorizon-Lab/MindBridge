# Zvec 0.8 adoption decisions

Evaluated 2026-10-26 using published Zvec 0.7.0 and 0.8.0 Linux x86-64 wheels,
CPython 3.12.14 and an Intel Xeon Gold 6230R. Upstream source was pinned to the
[v0.8.0 commit](https://github.com/alibaba/zvec/tree/7b7532784a781e20541b4e315919e6abc6ff0ecb).
Temporary experiment scripts, raw outputs and implementation plans were removed after
evaluation. This page retains the adoption decisions and their evidence limits.

## Adopted changes

- Upgrade to Zvec 0.8 and use native in-place merging after updates and deletes instead
  of rebuilding the entire collection for routine maintenance.
- Disable INT8 rotation in the projection recipe. Older derived projections rebuild from
  authoritative SQLite data without re-embedding content.
- Preserve NONE as the default, existing quantization values and the stemmed/bigram
  lexical recipe. Keep lifecycle coordination and resource-pressure safeguards.

The [accuracy-first retrieval results](2026-10-26-accuracy-first-retrieval.md) describe
subsequent FP32 rescoring and candidate-retention improvements.

## Compatibility and quality

Tests used 3,000 seeded normalized Gaussian FP32 vectors with seed 20261026.
Exact cosine truth came directly from the FP32 matrix. Native HNSW used m=16 and
ef_construction=200; grouped controls used ef=2048 and 30 queries.

| Zvec 0.8 grouped configuration | Recall@10 |
| --- | --- |
| NONE | 1.0000 |
| INT8, rotation on | 0.0000 |
| INT8, rotation off | 0.9833 |
| INT4, rotation off | 0.8067 |

The rotation failure reproduced in fresh interpreters and after reopening. Scaling queries
or refining scores did not repair discovery of the wrong candidates. A regression test
retains INT8 recall coverage across optimization and reopening.

A 0.7 FP32 cosine collection with stemmed full-text search opened writable under 0.8;
dense search, lexical search, upsert, flush and reopen succeeded. This covered the tested
format only. MindBridge still rebuilds derived projections when their recipe changes.

## Maintenance

After a 3,000-row build, five updates and five deletions, a single dirty-maintenance run
per configuration measured:

| Dimensions | Frozen 0.7 replacement (s) | Updated 0.8 merge (s) |
| --- | --- | --- |
| 128 | 2.422 | 1.318 |
| 1024 | 2.783 | 1.372 |

Both retained 2,995 live documents. The updated adapter preserved the collection directory
and avoided its full replacement workspace. Native merging still writes segment files.
These single shared-host observations establish the removal of full replacement; they
are not a stable throughput or zero-temporary-disk guarantee.

Dependency-only default-mode query measurements retained Recall@10 of 1.0, but timing
variation did not establish a general query speedup.

## Concurrency and durability audit (2026-10-27)

Ordinary dense and lexical queries, mutations, and flushes use shared handle leases.
Optimize, rebuild, replacement, and close use the exclusive gate. The lease protects
handle lifetime; native synchronization protects ordinary segment access. Mutations also
share a process-wide FD lock to preserve maintenance headroom across collections. Queries
do not take that process lock. This permits overlapping readers and reads during writes;
it does not promise independent writers or a transaction snapshot across query routes.
Zvec 0.8's [concurrency fixes](https://github.com/alibaba/zvec/pull/715) support this boundary.

The existing native concurrency test runs dense and Latin/bigram lexical readers beside
16 batches of 64 upserts, 32 deletes, and a flush. It checks reader progress in every batch,
persisted segment changes, and all 513 surviving documents after optimize and reopen.
A separate native case checks that FD-pressure flush maintenance releases its shared
lease before requesting exclusive replacement. These are correctness checks on the
installed wheel, not throughput measurements or a guarantee for every native platform.

The audit found one lifecycle omission: `doc_count` accessed native statistics without
a handle lease. A controlled regression reproduced close completing while that read was
still active. The property now holds a shared lease through the complete statistics read.
Its production caller already held the exclusive gate, so this establishes an adapter
boundary fix rather than evidence of an existing public SDK failure.

SQLite still commits records, embeddings, and outbox rows before Zvec changes. Applied
rows remain pending until a successful Zvec flush and are replayable after failure.
The audit does not justify changing that ordering, serializing queries, or removing
the process-wide FD safeguards.

## Capabilities retained outside the product API

- Uniform UINT4/7/8 reject cosine. The upstream
  [support matrix](https://github.com/alibaba/zvec/blob/7b7532784a781e20541b4e315919e6abc6ff0ecb/python/tests/test_uniform_quantization_support_matrix.py)
  restricts them to specific L2 configurations.
- INT4 lost grouped recall in this fixture. FP32 refinement improved ordinary search,
  but grouped search rejects refinement; see the
  [upstream restriction](https://github.com/alibaba/zvec/blob/7b7532784a781e20541b4e315919e6abc6ff0ecb/src/core/interface/index.cc#L754).
- Embedded Jieba works without external dictionary files. Six multilingual fixtures
  showed no gain over the existing combined lexical fields, and replacement lost
  English inflection matching. This small corpus does not establish language-wide quality.
- Python exposes IVF and DiskANN options, but no measured benefit justified a new public
  index setting. DiskANN was not performance-tested.
- No dedicated Python page-cache policy API or general HNSW PQ/OPQ configuration was
  established. The process-wide memory limit is not a cache-policy contract.

These results apply to the tested synthetic data and wheel architecture. They do not
establish production workload performance or quality on real model embeddings.
