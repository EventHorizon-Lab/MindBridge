# MindBridge 质量损失分层审查 — 2026-10-27

## 判断

有必要修复诊断的可辨识性，但现有证据不足以据此更换索引、调整检索策略或修改 reader。
“只看最终 QA 不足以定位损失”的判断成立；“来源全部命中、QA 仍错，所以是 reader 错”不成立。
五层应是可观测边界，而不是五个新的产品组件，也不是五个自动生成的因果标签。

从第一性原理看，最终分数是多个过程共同作用的结果。同一个错误答案可以来自原始输入缺失、
表示丢失、候选遗漏、证据选择、预算裁剪、媒体降级、感知失误、推理或评分误差。
只观测输出无法唯一反推原因；增加几个 span 也不会自动解决这个识别问题。
需要保存边界事实、明确标注粒度，并在必要时做固定变量的离线干预。

## 当前代码和已有实践

审查发现现有评测并非只有最终 QA：已有排名候选观测、来源组 recall、完整来源覆盖、
`dropped_hits`、部分 excerpt、最后一次准备的 generation request、模型和请求标识。
不足在于它们没有形成完整的题目级诊断记录，尤其缺少独立于返回 hits 的 answerer 输入。
自定义 backend 可以返回与输入不同的 hits，recall 可以加入初始排名之外的证据，
模型 adapter 还会裁剪和降级媒体。因此，候选列表和最终 hits 的差集不足以证明预算损失。

仓库的[2026-09-12 损失分解](2026-09-12-baseline-loss-decomposition.md)保存了真实历史实践：
ATM-main 中全部 gold 来源进入 window 的题目比例为 79.2%，该子集分数仍为 0.681；
离线重放中看似有效的时间排序，在完整 harness 和其他任务上出现退化并被撤回。
这些历史结果支持建立分层诊断和配对验证，但不能当作此 checkout 的新测量，也不能排除
来源内部缺少关键帧、表示不足或评分误差。本次工作没有找到这些历史运行的本地 samples 文件，
没有重现这些模型结果。

## 近期一手研究如何影响判断

- [Diagnosing the Fact-Grounding Gap，2026-09](https://arxiv.org/html/2609.17043v1)
  区分检索到目标 passage 和获得该推理步所需事实。实验提示 passage-level recall 会掩盖事实缺口。
  其标注包含经过人工校验的模型判断，研究环境是特定多跳 QA，不足以推断 MindBridge 的损失比例。
- [When Failures Propagate，2026-08](https://arxiv.org/html/2608.20627v1)
  用注入已知故障并重执行后续步骤检验归因，展示事后 coverage 可能把后果误认作原因。
  文中明确区分固定后续轨迹和重生成后续轨迹两种修复问题；内容扰动的深层失败样本很少，
  不能据此宣称某种归因器普遍有效。
- [Where Does Retrieval-Based Open-Ended Evaluation Fail，2026-09](https://arxiv.org/html/2609.30467v1)
  在开放医学事实验证中同时审查证据质量和 verifier 推理过程，提示扩大语料或模型不一定修复同一类错误。
  该结论来自不同任务和自动分类协议；本次采用其分开审查边界的思路，不采用自动分类结果作 gold。
- [OpenTelemetry trace 规范说明](https://opentelemetry.io/docs/concepts/signals/traces/)
  说明 trace/span 的关联能力。关联标识只证明记录属于哪个执行上下文，不证明证据充分性或因果关系。

这些研究是采用诊断方法的依据，不是本补丁提高最终准确率的证据。

## 根源修复

当前补丁把边界事实放在 benchmark 层统一解释，复用产品的私有观测机制；不改变检索、
prompt、模型选择、SDK/REST/MCP 合约或产品数据库。新增的五层为：

| 层 | 保存的事实 | 必须保留的未知 |
| --- | --- | --- |
| 可用输入 | 截止提问时间可用的已标注来源、候选总数、摄取失败 | 是否正确表示或索引 |
| 检索候选 | 产品已经计算的排名来源列表 | 未命中的具体原因 |
| 证据组织 | 最后一次交给 answerer 的完整来源，另列部分 excerpt | 这些来源是否包含充分事实 |
| reader 请求 | 最后一次准备的 record/asset、文本量、降级和成功状态 | 关键像素、语音或事实是否被理解 |
| 答案和评分 | QA 分数、拒答、运行错误、评分错误 | 哪一步导致结果 |

每题保留实际 `trace_id` 和 `answer_span_id`；一个 trace 可以包含多题，不能只靠 trace ID 区分。
新缓存保存原 trace 和证据组织观测；旧缓存缺少的信息保持未知，缓存不制造新执行 trace。
请求遥测尚未缓存，缓存重放的请求层明确不可用。当前观测保留最后一次调用，不能代替完整多轮轨迹。

来源组覆盖、标注缺失、观测缺失、空结果和未映射 record 分别处理；excerpt 不获得完整来源信用。
汇总单列每层观测数、覆盖测量分母、全部已标注来源齐全时的评分分母、均分、拒答和错误数。
`fact_span_coverage`、`causal_attribution`、表示/索引/感知/reader 质量保持未知。

## 无 gold span 的复核路径

新增 `mindbridge-bench review-samples`，按任务、arm、题型、结果状态和来源标注状态确定性抽样，
保留数据和评测 hash、trace 及每层观测。标注字段全部为空、状态为 pending；不会调用模型制造答案证据。
保留各层人口和抽样数量，避免把分层样本的不加权均值误报为整体指标。

人工复核需要回到原始来源标记字符区间、视频时间/帧或音频时间及单位，记录充分性、反证和未知，
由第二位独立审查者复核后裁决分歧，再安排原件、存储表示、选择证据和实际请求的配对干预。
本次没有人工审查者和可用运行样本，未执行这项人工标注，也没有声称形成新的 gold。
命令和字段解释见[当前评测指南](../benchmarking.md#five-layer-quality-diagnosis)。

## 验证边界

新增确定性回归覆盖五层关联、输入与返回 hits 不同、并发题目 span、缺失与空结果、
未知来源映射、部分 excerpt、缓存和人工抽样。真实本地 SDK 测试验证私有观测异常不会影响答案。
这些检查证明诊断记录和计算规则，不证明真实模型质量提高。
本补丁没有修改 prompt、模型或检索策略，未发起新的外部模型质量评测。

本轮实际验证：747 项相关测试通过，5 项 CLI 测试通过；其中 12 项为本次诊断专项测试。
修改涉及的模块通过 Ruff 格式和静态检查；诊断模块、缓存、结果和遥测的专项 mypy 检查通过。
四份相关文档通过固定版本 Markdown 检查，117 个链接通过检查；锁文件检查和 diff 空白检查通过。
